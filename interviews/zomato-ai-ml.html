01
RAG · LangChain · Vector databases

How would you build an end-to-end RAG pipeline using LangChain?

What is the interviewer testing?

This question tests your understanding of how to build a system that retrieves relevant information from a knowledge base and uses a language model to generate an answer grounded in that information. You should understand document processing, embeddings, retrieval, generation, and evaluation.

Understand the concept

RAG stands for Retrieval-Augmented Generation. It combines information retrieval with text generation. Instead of depending only on its training data, a language model receives relevant external information when answering a question.

A RAG system typically has two main stages:

  • Indexing: Prepare documents, split them into chunks, create embeddings, and store them for retrieval.
  • Retrieval and generation: Retrieve relevant content for a user query and provide it to the language model.

Step-by-step implementation

1

Load the documents

Collect information from PDFs, text files, web pages, or internal company documents. Use appropriate document loaders to extract the content.

2

Split documents into chunks

Divide long documents into smaller text segments. Chunk size and overlap influence how much context is available during retrieval.

3

Generate embeddings

Convert each chunk into a numerical vector using an embedding model. Semantically similar text should generally have similar vector representations.

4

Store the vectors

Store the embeddings alongside their source text and metadata in a vector store, such as FAISS or Chroma, so that relevant chunks can be retrieved efficiently.

5

Retrieve relevant information

When a user submits a question, search the knowledge base for the chunks most relevant to the query. Depending on the task, use metadata filtering, hybrid search, or reranking.

6

Generate the response

Pass the question and retrieved context to the language model. Instruct it to answer using the supplied evidence and to acknowledge when the information is insufficient.

7

Evaluate the results

Test retrieval relevance, answer correctness, completeness, latency, and groundedness. Inspect incorrect answers to identify whether the problem comes from retrieval or generation.

Practical example

Example scenario

Imagine building a chatbot that answers questions about company policies. An employee asks, “How many days of annual leave do I receive?”

The retriever finds the relevant passage in the employee handbook. The language model uses that passage to formulate an answer. A well-designed system should avoid inventing a leave entitlement when the handbook does not contain the required information.

Common challenges and improvements

  • Poor retrieval: Experiment with embeddings, hybrid search, metadata filters, and reranking.
  • Incorrect answers: Require answers to be grounded in retrieved evidence and test factual accuracy.
  • Bad chunking: Adjust chunk size and overlap based on document structure and task requirements.
  • Slow responses: Optimize retrieval, caching, model selection, and the number of context tokens.
  • Outdated content: Establish a process for updating documents and removing obsolete information.
Key takeaway

Remember the sequence: Load documents → Split into chunks → Generate embeddings → Store vectors → Retrieve context → Generate an answer → Evaluate quality.

02
NLP · Embeddings · Representation learning

What is the difference between BERT embeddings and Word2Vec embeddings?

What is the interviewer testing?

The interviewer wants to know whether you understand how words are represented numerically, why context matters in NLP, and how different embedding approaches affect downstream tasks.

Understand the concept

Word2Vec learns word vectors from surrounding-word patterns in a corpus. In its standard form, a word has one learned vector regardless of the sentence in which it appears.

BERT is a Transformer-based language model that generates context-dependent representations. The representation for a word can change depending on the other words in the sentence.

Key differences

  • Context: Standard Word2Vec assigns a static vector to a word. BERT produces contextual representations.
  • Ambiguous words: Word2Vec does not naturally distinguish different meanings of the same word in different sentences. BERT can represent those meanings differently based on context.
  • Architecture: Word2Vec commonly uses a shallow neural network with CBOW or Skip-gram objectives. BERT uses a multi-layer Transformer encoder.
  • Training: Word2Vec learns word vectors from local context windows. Original BERT training included masked-language modeling and, in its original formulation, next-sentence prediction.
  • Compute: Word2Vec is generally smaller and cheaper to use. BERT typically requires more computational resources.

Practical example

Compare the context

Consider these two sentences:

Sentence A: “She deposited money at the bank.”

Sentence B: “They sat beside the river bank.”

Standard Word2Vec uses the same learned vector for the word “bank” in both sentences. BERT can produce different contextual representations because the surrounding words indicate different meanings.

When would you use each?

  • Word2Vec: Lightweight applications, traditional NLP pipelines, or tasks where static word representations are sufficient.
  • BERT: Context-sensitive classification, question answering, named entity recognition, and sentence representation tasks when a suitable BERT-based model is used.
Key takeaway

Word2Vec produces static word vectors. BERT produces contextual representations that reflect how words are used in a sentence.

03
Tokenization · Sentiment analysis · NER

How can excessive tokenization affect sentiment analysis and named entity recognition?

What is the interviewer testing?

This question tests your understanding of tokenization, the way models process text, and the relationship between input representation and downstream model performance.

Understand tokenization

Tokenization divides text into units that a model can process. Depending on the tokenizer, these units might be words, subwords, characters, or punctuation symbols.

Subword tokenization helps models handle rare and unfamiliar words. However, when a word is split into many small pieces, the model may need more tokens to represent the same sentence. This can affect computational cost and how information is represented.

How can it affect sentiment analysis?

  • Longer sequences: Excessive splitting increases sequence length and can increase memory use and processing time.
  • Negation and context: A tokenizer must preserve useful information about expressions such as “not good.” Poor downstream handling of the sequence may lead to incorrect sentiment predictions.
  • Rare or informal language: Slang, misspellings, emojis, and domain-specific words may be split into unfamiliar pieces, potentially making interpretation harder.

Tokenization alone does not necessarily cause incorrect sentiment predictions. The effect depends on the tokenizer, model training, available context, and the quality of the input data.

How can it affect named entity recognition?

Named entity recognition (NER) identifies entities such as people, organizations, locations, and dates.

  • Subword alignment: A name may be split into multiple tokens, so the system must map token-level predictions back to the complete entity correctly.
  • Uncommon names: Rare names and unfamiliar spellings may be difficult to identify if the model has limited relevant training examples.
  • Sequence truncation: Very long tokenized inputs may exceed model limits, potentially removing entities near the end of the text.

How would you investigate the problem?

1

Inspect tokenization

Compare original text with its tokenized representation, especially for names, abbreviations, slang, and domain terms.

2

Check sequence lengths

Measure how often text exceeds the model's input limit and whether truncation removes relevant information.

3

Evaluate task-specific errors

For sentiment analysis, inspect class-wise precision and recall. For NER, examine entity-level precision, recall, and F1 score.

4

Test a suitable solution

Compare a domain-appropriate tokenizer or model, improve training examples, and validate any changes on a held-out dataset.

Key takeaway

Tokenization affects sequence length and how text is represented. Investigate tokenization alongside model behavior, input truncation, data quality, and task-specific evaluation metrics.

04
Transformers · Position · Attention

What are positional embeddings, and how does Rotary Positional Embedding (RoPE) work?

What is the interviewer testing?

The interviewer wants to know whether you understand how Transformer models represent token order and why position information is important for language understanding.

Why do Transformers need position information?

Self-attention allows a Transformer to relate tokens to one another. But token content alone does not fully express the order in which words appear.

Consider “The dog chased the cat” and “The cat chased the dog.” The words overlap, but their order changes the meaning. Position information helps the model distinguish these relationships.

What are positional embeddings?

Positional embeddings or encodings provide information about where tokens occur in a sequence. Some Transformer architectures add position vectors to token representations, while others incorporate position information in other parts of the model.

Different approaches include learned absolute positional embeddings, sinusoidal encodings, and relative-position methods.

How does RoPE work?

RoPE stands for Rotary Positional Embedding. It incorporates position information by applying position-dependent rotations to components of the query and key vectors used in attention.

1

Start with query and key vectors

The attention mechanism generates query and key representations from token representations.

2

Apply position-dependent rotations

RoPE rotates pairs of vector components according to the token's position and frequency-dependent rotation angles.

3

Calculate attention scores

Attention uses the transformed query and key vectors. Their interaction incorporates information related to the relative positions of tokens.

4

Use position-aware attention

The resulting attention scores help the model process token relationships while taking sequence position into account.

Why is RoPE useful?

  • It integrates positional information into query and key representations.
  • Its attention formulation naturally captures relative-position information.
  • It is used in a number of modern Transformer language models.
  • Its behavior at sequence lengths beyond training requires careful model-specific evaluation; RoPE alone does not guarantee reliable unlimited context.
Key takeaway

Positional information helps a Transformer understand token order. RoPE incorporates position-dependent rotations into query and key vectors so attention can account for token positions.

05
Quantization · Optimization · Inference

How does model quantization affect inference speed, memory usage, and accuracy?

What is the interviewer testing?

This question checks your understanding of model optimization and how to balance computational cost, latency, memory requirements, and predictive quality when deploying AI models.

Understand quantization

Quantization represents model weights and, in some approaches, activations using lower-precision numerical formats. For example, a model may use lower-bit representations instead of storing all values in a higher-precision format.

Lower-precision representations can reduce memory requirements and may improve inference efficiency when the hardware and software support the chosen format.

Three important effects

1

Memory usage

Using fewer bits per parameter generally reduces the memory needed to store model weights. Actual memory savings also depend on metadata, runtime overhead, activations, and the quantization implementation.

2

Inference speed

Quantization may improve inference speed by reducing memory traffic or using efficient low-precision hardware operations. Speed gains are not guaranteed and depend on the model, hardware, batch size, and inference engine.

3

Model accuracy

Quantization introduces approximation error. Some models tolerate lower precision well, while others experience measurable quality degradation, especially under aggressive quantization.

Common quantization approaches

  • Post-training quantization (PTQ): Quantize a trained model without performing a full retraining process. Some methods use calibration data.
  • Quantization-aware training (QAT): Simulate quantization effects during training so the model can adapt to them.
  • Weight-only quantization: Quantize model weights while leaving other computations at higher precision, depending on the implementation.

How would you evaluate a quantized model?

1

Establish a baseline

Measure the original model's task performance, memory usage, latency, and throughput.

2

Quantize the model

Apply a suitable quantization method and verify that the resulting model loads and runs correctly.

3

Run the same evaluation set

Compare original and quantized outputs on representative inputs. Use metrics appropriate to the task, such as accuracy, F1, or a human-reviewed quality evaluation.

4

Compare deployment performance

Measure latency, throughput, and memory under realistic deployment conditions. Choose the best trade-off for the application rather than optimizing a single metric.

Key takeaway

Quantization can reduce model memory and improve inference efficiency, but its effects on speed and accuracy depend on the quantization method, model, hardware, and workload. Measure the trade-offs before deployment.

06
Agentic AI · Tool use · Reliability

How would you analyze and improve an Agentic AI pipeline?

What is the interviewer testing?

The interviewer wants to see whether you understand how AI agents plan tasks, use tools, observe results, and decide what to do next. They may also be assessing your ability to debug multi-step workflows and improve their reliability.

Understand the concept

An Agentic AI pipeline is a workflow in which a model can select actions or tools and use their results to work toward a goal. Depending on the design, an agent may plan tasks, call APIs, retrieve information, maintain state, and repeat steps until a stopping condition is met.

Unlike a simple one-shot prompt, an agentic workflow may contain several decisions and tool interactions. Each additional step introduces opportunities for failure.

Common components

  • Goal and instructions: Define the task and its constraints.
  • Planner or reasoning step: Determine the next action or subtask.
  • Tool selection: Choose an available tool or API.
  • Execution: Run the selected action and obtain its result.
  • Observation: Interpret the result and update the current state.
  • Control flow: Continue, retry, ask for clarification, or stop.
  • Evaluation and monitoring: Track correctness, safety, cost, and reliability.

Step-by-step improvement process

1

Define success criteria

Specify what a successful result looks like. Measure task completion, factual accuracy, instruction following, tool selection, and policy compliance where relevant.

2

Trace each step

Record model inputs and outputs, selected tools, tool responses, execution time, and errors. Redact sensitive information from logs.

3

Identify the failure point

Determine whether the failure came from planning, an incorrect tool call, bad tool output, missing context, an incorrect interpretation, or a poor stopping decision.

4

Improve tool reliability

Validate tool arguments, define clear tool descriptions, handle API errors, set timeouts, and use controlled retries where appropriate.

5

Set boundaries and safeguards

Restrict tool permissions, validate untrusted inputs, enforce step and token limits, and require confirmation before consequential actions when appropriate.

6

Run regression evaluations

Test the updated agent against representative tasks and known failure cases. Compare success rate, accuracy, latency, cost, and safety before and after the changes.

Practical example

Example scenario

Imagine an agent that helps users find suitable AI job opportunities. It receives a user profile, searches a job database, filters opportunities, and summarizes the best matches.

If the agent repeatedly recommends irrelevant roles, trace its workflow. It may be extracting skills incorrectly, using unsuitable search filters, or ranking results poorly. Improve the faulty stage and evaluate the updated workflow against a fixed set of representative user profiles.

What metrics would you monitor?

  • Task success rate: How often does the agent complete the intended task?
  • Tool-call accuracy: Does it select and invoke the appropriate tools correctly?
  • Factuality: Are its claims supported by reliable evidence?
  • Latency: How long does the full workflow take?
  • Cost: How many model tokens and tool calls are required?
  • Safety: Does it follow constraints and avoid unauthorized actions?
Key takeaway

Trace the complete workflow, identify the failing stage, fix the underlying cause, and validate the improvement with repeatable evaluations. A reliable agent needs clear boundaries, robust tool handling, and measurable success criteria.

How to prepare effectively

Use these questions to build understanding rather than memorizing answers word for word. Practice explaining each concept in your own language and connecting it to a practical application.

  • Understand the fundamentals Learn the core concept, how it works, and when it is useful.
  • Practice explaining aloud Explain each answer in two or three minutes without reading the page.
  • Prepare trade-offs Be ready to discuss limitations, alternatives, and ways to improve a system.
  • Connect concepts to evaluation Explain how you would test correctness, identify failures, and measure improvements.
