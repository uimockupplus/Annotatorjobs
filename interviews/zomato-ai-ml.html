Q01 Retrieval & generation

How would you build an end-to-end Retrieval-Augmented Generation (RAG) pipeline using LangChain?

A RAG system combines information retrieval with a language model. Rather than relying only on knowledge learned during training, it retrieves relevant information from an external source and provides that context to the model when generating an answer.

Step 1: Prepare the documents

Collect the information the application needs to answer questions about. Sources might include PDFs, product documentation, knowledge-base articles, and structured records.

  • Load documents from their original sources.
  • Clean irrelevant text, duplicates, and formatting noise.
  • Split longer documents into smaller, overlapping chunks.
  • Preserve metadata such as document title and source.

Step 2: Generate embeddings

An embedding model converts each text chunk into a numerical vector. These vectors represent semantic information, allowing the retrieval system to find related chunks even when their wording differs from the question.

Step 3: Store vectors in a database

Save the embeddings alongside their text and metadata in a vector database or another suitable vector index. Depending on the application, retrieval may use cosine similarity, dot product, or another scoring strategy.

Step 4: Retrieve relevant information

When a user asks a question, convert the query into an embedding and search for relevant chunks. Improve retrieval with metadata filters, hybrid keyword-and-vector search, or a reranking model when necessary.

Step 5: Generate a grounded answer

Pass the question and retrieved context to the language model. Instruct it to answer using the supplied evidence and to acknowledge when the available information is insufficient.

Typical RAG architecture 
User question
      ↓
Query embedding
      ↓
Vector or hybrid retrieval
      ↓
Relevant document chunks
      ↓
Optional reranking
      ↓
Prompt + retrieved context
      ↓
Language model
      ↓
Answer with supporting sources

Step 6: Evaluate the pipeline

  • Retrieval quality: Does the system retrieve the documents needed to answer the question?
  • Faithfulness: Is the generated answer supported by the retrieved context?
  • Relevance: Does the answer address the user's actual question?
  • Latency and cost: How long does each request take, and how many resources does it consume?
Key takeaway

A good RAG pipeline is more than a vector database connected to an LLM. Document quality, chunking, retrieval, reranking, prompt design, grounded generation, and evaluation all affect reliability.

Q02 NLP & embeddings

What is the difference between BERT embeddings and Word2Vec embeddings?

Word2Vec and BERT both produce vector representations of text, but they differ in how those representations are learned and how they capture context.

Aspect Word2Vec BERT
Architecture Shallow neural-network architecture Transformer encoder
Context Generally uses a fixed vector for each word Produces context-dependent token representations
Ambiguous words Typically uses the same learned vector for a word Can represent a word differently depending on context
Training Commonly uses CBOW or Skip-gram Original BERT uses masked language modelling and next-sentence prediction
Typical uses Word similarity and lightweight NLP features Contextual NLP features, classification, and fine-tuning
Compute needs Usually lower Usually higher

Example: Understanding context

Consider these two sentences:

  • "I deposited money at the bank."
  • "We sat on the bank of the river."

A conventional Word2Vec model assigns the word "bank" one learned word vector. It does not automatically create separate vectors for its financial and geographical meanings.

BERT processes the surrounding words and can produce different contextual representations for "bank" in these two sentences.

How does Word2Vec work?

  • CBOW: Predicts a target word using surrounding context words.
  • Skip-gram: Predicts surrounding context words from a target word.

How does BERT work?

BERT uses a bidirectional Transformer encoder. Self-attention allows a token's representation to incorporate information from other tokens in the input, including tokens before and after it.

Key takeaway

Word2Vec is useful for lightweight word-level representations. BERT provides contextual token representations and can be adapted to complex NLP tasks. For semantic search, sentence-transformer models are often used to generate sentence-level embeddings instead of directly using raw BERT token outputs.

Q03 Text processing

How does tokenization affect sentiment analysis and Named Entity Recognition (NER)?

Tokenization divides text into smaller units that a model can process. Depending on the tokenizer, these units may be words, subwords, characters, or other tokens.

Tokenization affects how a model represents words, handles unfamiliar terms, preserves entities, and interprets sentiment. Poor tokenization choices can introduce errors before the model starts making predictions.

Impact on sentiment analysis

  • Negation: "Not good" conveys a different sentiment from "good." A model must preserve and interpret the relationship between these tokens.
  • Contractions: Words such as "isn't" and "don't" may be split into multiple tokens.
  • Emojis and informal language: Reviews often contain emojis, abbreviations, misspellings, and slang that influence sentiment.
  • Domain-specific terms: Product names, abbreviations, and new expressions may be divided into multiple subword tokens.

Impact on Named Entity Recognition

NER identifies entities such as people, organizations, locations, products, and dates. Subword tokenization can split a single entity across multiple tokens.

For example, a company name may be divided into several subword pieces. The training and inference pipelines must map token-level predictions back to the correct entity span.

How can tokenization-related errors be reduced?

  1. Choose a tokenizer compatible with the model architecture and its training process.
  2. Inspect how representative domain-specific text is split into tokens.
  3. Handle special characters, Unicode text, emojis, and normalization consistently.
  4. Align NER labels correctly when words are split into subword tokens.
  5. Evaluate difficult examples, including misspellings, rare names, and multilingual text.

How would you measure the impact?

  • Sentiment analysis: Compare accuracy, precision, recall, and F1-score across relevant test sets.
  • NER: Evaluate entity-level precision, recall, and F1-score.
  • Error analysis: Review failures to distinguish tokenization problems from model prediction or label-alignment errors.
Key takeaway

Tokenization is part of the model pipeline, not just a preprocessing detail. Consistent tokenization and correct label alignment are particularly important for NER and domain-specific text.

Q04 Transformer architecture

What are positional embeddings, and how does Rotary Positional Embedding (RoPE) work?

Transformer attention mechanisms need information about token positions to reason about word order. Without positional information, self-attention alone does not distinguish all possible arrangements of the same tokens.

What are positional embeddings?

Positional embeddings or encodings introduce information about where tokens occur in a sequence. In one common approach, a positional representation is combined with the token embedding before the Transformer processes the sequence.

Different Transformer architectures use different positional methods, including learned absolute positional embeddings, sinusoidal encodings, and relative-position approaches.

What is RoPE?

Rotary Positional Embedding incorporates position information by applying position-dependent rotations to pairs of dimensions in the query and key vectors used by attention.

Rather than simply adding a positional vector to a token embedding, RoPE modifies query and key representations before their attention scores are calculated.

Why is RoPE useful?

  • It incorporates positional information into attention calculations.
  • Attention relationships naturally depend on relative position differences.
  • It is used in many modern decoder-only Transformer models.
  • It can support long-context designs, although reliable extension beyond a model's trained context length may require additional techniques.

What happens when context length increases?

A model trained with one context length may not perform equally well at much longer lengths. Positional behaviour, attention patterns, memory consumption, and the model's training distribution can all affect performance.

Techniques such as RoPE scaling can help adapt certain models to longer contexts, but the results should be evaluated rather than assumed.

Key takeaway

Positional information helps Transformers interpret token order. RoPE applies position-dependent rotations to query and key vectors, allowing position to influence attention scores through their interactions.

Q05 Model optimization

What is model quantization, and how does it affect inference performance and accuracy?

Model quantization reduces the numerical precision used to represent model weights and, in some approaches, activations. For example, a model may use lower-precision representations instead of storing all weights in 32-bit floating-point format.

The objective is to reduce memory requirements and potentially improve inference speed, energy efficiency, and deployment cost.

Common numerical formats

  • FP32: 32-bit floating-point representation, commonly used as a full-precision baseline.
  • FP16: 16-bit floating-point representation, often used for faster, lower-memory inference on supported hardware.
  • BF16: 16-bit floating-point representation with a wider exponent range than FP16.
  • INT8: 8-bit integer quantization, often useful for reducing memory and accelerating supported workloads.
  • 4-bit quantization: Uses fewer bits per quantized value and can substantially reduce weight memory, though quality and speed depend on the method and hardware.

How does quantization affect memory?

As a rough illustration, storing one billion parameters at four bits each requires approximately 0.5 GB of raw parameter storage in decimal units, compared with approximately 4 GB at 32 bits per parameter.

These figures represent weight storage only. Actual deployment memory also includes quantization metadata, temporary tensors, runtime overhead, and the key-value cache used by many language models.

What is the trade-off?

  • Memory: Lower-bit representations usually reduce weight storage.
  • Speed: Inference may become faster if the hardware and software efficiently support the selected format.
  • Accuracy: Quantization can change model outputs and reduce quality, especially with aggressive quantization or sensitive tasks.
  • Compatibility: Not every device or inference engine supports every quantization method efficiently.

How would you evaluate a quantized model?

  1. Establish a baseline using the original model.
  2. Apply a suitable quantization method.
  3. Test both versions on representative real-world inputs.
  4. Compare task quality, factuality, and failure cases.
  5. Measure latency, throughput, peak memory, and hardware usage.
  6. Select the configuration that meets the application's quality and performance requirements.
Key takeaway

Quantization is an optimization trade-off. The best configuration is not necessarily the one with the fewest bits; it is the one that delivers acceptable quality, latency, memory usage, and cost for the target workload.

Q06 Agentic systems

How would you analyse and improve an Agentic AI pipeline?

An Agentic AI system uses a model to decide what to do next and may interact with tools, external services, or other components to complete a task. Unlike a simple one-shot prompt-response system, an agent may plan actions, inspect results, and repeat steps until it reaches a stopping condition.

What does an agent pipeline look like?

Typical agent workflow 
User request
      ↓
Understand the task
      ↓
Plan the next action
      ↓
Select a tool or action
      ↓
Execute the action
      ↓
Inspect the result
      ↓
Continue, recover, or finish
      ↓
Return the final response

Step 1: Define the task and success criteria

Before improving an agent, identify what a successful result means. A research agent, coding agent, and customer-support agent need different evaluation criteria.

Useful measures may include task-completion rate, factual correctness, successful tool execution, latency, cost, and adherence to safety requirements.

Step 2: Identify where failures occur

  • Planning errors: The agent chooses an unsuitable sequence of actions.
  • Tool-selection errors: It calls the wrong tool or supplies invalid arguments.
  • Execution errors: A tool fails, times out, or returns unexpected data.
  • Reasoning errors: The agent misinterprets evidence or draws an unsupported conclusion.
  • Looping: It repeats actions without making useful progress.
  • Context problems: Important information is lost or ignored during multi-step tasks.

Step 3: Improve reliability

  • Give tools clear descriptions and strict input schemas.
  • Validate tool arguments before execution.
  • Add timeouts, bounded retries, and explicit error handling.
  • Set maximum step counts and meaningful stopping conditions.
  • Keep structured logs of decisions, tool calls, outputs, and errors.
  • Require confirmation for sensitive or irreversible actions.
  • Treat retrieved documents and external tool outputs as untrusted input where appropriate.

Step 4: Evaluate changes systematically

Build a test set containing common tasks, edge cases, ambiguous instructions, tool failures, and adversarial inputs. Run the baseline and improved versions on the same tasks.

Compare success rates, tool-call accuracy, unsupported claims, recovery from errors, response quality, average latency, and cost per completed task.

Step 5: Choose the simplest effective architecture

Not every workflow requires a fully autonomous agent. A deterministic sequence of steps may be faster, cheaper, and easier to test. Use agentic decision-making where adapting actions to changing information provides a measurable benefit.

Key takeaway

Improving an agent means measuring the complete task outcome, locating failure points, strengthening tool execution and control flow, and testing changes against a representative evaluation set. More autonomy does not automatically mean better performance.
